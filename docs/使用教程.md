# HyperMux 使用教程

自托管家庭影视系统的完整使用指引：部署后端 → 配置管理后台 → 接入 OpenList 数据源 → 上架影片 → 手机 / TV / Web 三端观看。

> 适用版本：server 1.0.x · admin 0.1.x · 手机 App 0.1.12 · TV App 0.1.0 · web 0.1.x
> 接口契约详见 [plans/30-api-contract.md](./plans/30-api-contract.md)，部署运维见 [plans/70-deploy-ops.md](./plans/70-deploy-ops.md)。

---

## 1. 系统总览

```
┌──────────────── 使用者端 ────────────────┐   ┌──── 管理端 ────┐
│ 手机 App          TV App         Web 播放端 │   │  管理面板       │
│ hyper-mux-android hyper-mux-android-tv hyper-mux-web │ hyper-mux-admin │
└───────────────┬───────────────────────────┘   └───────┬────────┘
                │ /api/app/**（普通用户，role=0）        │ /api/admin/**（管理员，role=1）
        ┌───────┴───────────────────────────────────────┴───────┐
        │        hyper-mux-server（Spring Boot，:8080）          │
        │  API + 管理面板同源托管 + 图片代理 /img + App 自更新     │
        └───────┬───────────────────────────────┬───────────────┘
                │ 元数据刮削                      │ 视频直链（不中转流）
          豆瓣 / TMDB                        OpenList 数据源
                数据库：PostgreSQL（启动时自动幂等建表）
```

- **后端不中转视频流**：播放时后端只把 OpenList 路径拼成公网直链返回给客户端，客户端直连播放。
- **角色模型**：普通用户（role=0，手机 / TV / Web 多端通用，断点进度跨端同步）与管理员（role=1，仅管理面板）。两端 token 互不通用（互访返回 403）。

## 2. 快速启动（后端 + 管理面板）

前置：JDK 17、Node 18+、PostgreSQL。

```bash
# 1) 配置数据库：复制模板并按本机修改（该文件已被 gitignore，勿提交真实凭据）
copy hyper-mux-server\src\main\resources\application-dev.yml.example ^
     hyper-mux-server\src\main\resources\application-dev.yml

# 2) 构建并启动后端（首次启动自动建表；库内无管理员时自举创建 admin）
cd hyper-mux-server
mvn -B package -DskipTests
java -jar target\hypermux-server.jar

# 3) 构建管理面板（产物 ../admin-dist，后端同源托管）
cd ..\hyper-mux-admin
npm install
npm run build:dist

# 4) 浏览器打开
#    http://127.0.0.1:8080/     管理面板，初始账号 admin / Admin@1234
#    http://127.0.0.1:8080/swagger-ui.html   接口文档（dev）
#    http://127.0.0.1:9090/actuator/health   健康检查（管理端口，不对外）
```

> ⚠️ 上线前：修改 admin 密码并清空 `admin-bootstrap-password`；用环境变量覆盖 `JWT_SECRET` 与 `HYPERMUX_SECRET`。
> Windows 中文系统建议设置 `JAVA_TOOL_OPTIONS=-Dfile.encoding=UTF-8`，避免日志/源码中文乱码。

生产环境变量（可全部替代 yml）：`SPRING_PROFILES_ACTIVE`、`PG_HOST/PG_PORT/PG_DB/PG_USER/PG_PASSWORD`、`HYPERMUX_STATIC_DIRS`、`HYPERMUX_IMAGE_DIR`、`JWT_SECRET`、`HYPERMUX_SECRET`、`ADMIN_BOOTSTRAP_PASSWORD`。

## 3. 接入 OpenList 数据源

管理面板 → **数据源**：

1. 点「新建数据源」：填名称、OpenList 站点地址（如 `http://<openlist-host>:5244`）、Token（算法令牌，需有列目录与读取权限）、默认根目录。
2. 「测试连通」验证：后端两步探测（版本 + 列目录），失败会给出具体原因。
3. Token 以 **AES-256-GCM 加密落库**，永不出后端；删除数据源有守卫（仍被影片引用时返回 409/423 阻止删除）。

## 4. 影片上架（核心流程）

管理面板 → **影视类型**：先建分区（电视剧 / 电影 / 综艺 / 动漫…，可自定义、可排序、可停用）。TV / 手机首页按类型分区展示。

管理面板 → **影片 → 新建影片**，两条路径：

**A. 从 OpenList 目录导入（推荐）**
1. 「从数据源选目录」：浏览 OpenList 目录树，选中影片所在目录；
2. 后端自动解析：片名 / 年份 / 季 / 剧集列表（自然序排序，支持 S01E01、第 X 集、1080p 等常见命名，可配 ignore 规则与 NFO）；
3. 解析结果填充表单，可再编辑。

**B. 手动新建 + 剧集粘贴导入**
- 手填片名等信息；剧集列表支持一次性粘贴多行路径（每行一条直链路径）。

**元数据与图片刮削**
- 表单里点「刮削」：按片名（+年份）从 **TMDB 或 豆瓣**（系统设置页切换，TMDB 需配 API Key）回填 年份 / 评分 / 国家 / 语言 / 简介 / 标签 / 海报；
- 影片详情页点「刮削图片」：抓海报 + 16:9 横图，**上传到该影片的 OpenList 目录**（`images/poster.*`、`backdrop.*`），并把 `cover_url/backdrop_url` 回写为 OpenList 直链（与视频同源，规避远程图床防盗链失效）；列表页支持批量「补横图」。

**发布规则**：保存为草稿 → 点「发布」后对客户端可见；「下架」立即不可见；删除会连带剧集与观看断点，不可恢复。

> 客户端可见性三铁律：**已发布 + 所属类型启用 + 集数 > 0**，缺一即 404（与"不存在"表现一致，不泄露存在性）。

## 5. 用户管理

管理面板 → **用户**：

- 新建用户：用户名 3~32 位字母/数字/下划线；初始密码 6~20 位（限字母/数字/`_`/`.`）；角色选 **普通用户** 或 **管理员**；
- 普通用户可直接在手机 App / TV App / Web 播放端登录，同一账号多端通用，观看进度跨端同步；
- 停用 = 立即无法登录（每请求回库校验，token 即时失效）；删除 = 连带清理其全部观看断点；
- 重置密码：随机生成（一次性明文展示）或自定义；
- 登录接口对密码只校验长度 6~20（不做字符集限制），并有失败限流（429）。

## 6. 三端客户端使用

### 6.1 手机 App（hyper-mux-android）

- 登录页底部「服务器配置」：
  - **公开服务器**：仅当该 APK 构建时注入了预置地址才出现此档（见 §6.4）；
  - **自定义服务器**：填你自己的后端地址（如 `http://192.168.1.10:8080`），可先「测试连接」；
- 功能：首页类型分区 + 继续观看、搜索、影片详情 / 剧集、播放（倍速 / 长按快进）、断点续播、历史记录、**下载缓存**（默认仅 Wi-Fi）、App 内自更新；
- 改服务器后需重新登录（token 与服务器绑定）。

### 6.2 TV App（hyper-mux-android-tv）

- 遥控器全键操作：焦点卡片导航、自绘字符键盘（登录 / 搜索 / 地址输入）；
- 服务器配置逻辑与手机端一致；TV 构建还可用 `-PhypermuxApiBase=http://<局域网后端>` 预填自定义地址，免去遥控器手输；
- 功能与手机端对齐（浏览 / 播放 / 历史 / 下载 / 自更新），UI 为 10 英尺视距大字号布局。

### 6.3 Web 播放端（hyper-mux-web）

```bash
cd hyper-mux-web
npm install
npm run build     # 产物 dist/，任意静态服务器部署（与后端同源或反代 /api 均可）
```

用**普通用户**账号登录，功能：首页 / 类型 / 搜索 / 详情 / 播放（ArtPlayer）/ 历史 / 我的。

### 6.4 构建 App 时注入「公开服务器」（可选）

想让分发出去的 App 自带一个公共节点（用户开箱即用、界面上不显示地址）：

```bash
cd hyper-mux-android   # 或 hyper-mux-android-tv
gradle assembleRelease -PhypermuxPublicServerUrl=http://your-server:8080
```

- 不注入 → App 登录页只有「自定义服务器」，用户必须自填地址；
- 注入 → 登录页默认「公开服务器」档，UI 全程不出现该地址；用户仍可切到自定义；
- 老用户升级安全：旧版存过的地址在新版自动以「自定义」模式保留，不会断服。

## 7. App 自更新

- 管理面板 → **App 发布**：上传 mobile / tv 两个平台的 APK（存到服务端 `~/.hypermux/apks/{platform}-latest.apk`），维护版本号与更新说明；
- App 启动检查 `/api/app/update/check`（免鉴权；24h 节流，设置页可手动检查），有新版本弹窗 → 经 `/api/app/update/download` 流式下载并调起安装（需用户授予"安装未知应用"权限）；
- 某平台未发布时检查返回 204，App 不打扰。

## 8. 图片代理

客户端所有远程图片统一走 `GET /img?u=<url编码的远程图址>`：后端带 Referer 下载（豆瓣图床无 Referer 会 418）、落盘缓存（默认 `~/.hypermux/images`，`HYPERMUX_IMAGE_DIR` 可改）后由本站出图，支持 ETag / 7 天强缓存。已配置数据源域名同时放行。

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 影片在后台可见、客户端 404 | 检查三铁律：已发布？类型启用？集数 > 0？ |
| App 登录 403「该账号无此端访问权限」 | 用管理员账号登了客户端（或反之）；角色与端不匹配 |
| 登录 429 | 失败限流，稍后再试 |
| 换服务器后登录正常但数据不对 | token 与服务器绑定，需退出重登 |
| 封面图不显示 | 走 `/img` 代理；确认后端能出网访问图床，或改用「刮削图片」把图落到 OpenList |
| 播放 403 / 无直链 | OpenList 源 Token 失效或路径变更，到数据源页「测试连通」 |
| Windows 日志中文乱码 | 设 `JAVA_TOOL_OPTIONS=-Dfile.encoding=UTF-8` |
| mvn package 报 `Unable to rename ... jar.original` | jar 正在运行占用文件，先停进程再打包 |
| 改了 JWT_SECRET / HYPERMUX_SECRET 后全部登录失效 | 预期行为：旧 token 与已加密的源 Token 都失效，需重配源 Token |

## 10. 安全清单（上线前）

- [ ] 修改 admin 初始密码（`Admin@1234` 仅是 dev 自举默认值）并清空 `admin-bootstrap-password`
- [ ] 覆盖 `JWT_SECRET`、`HYPERMUX_SECRET` 默认值
- [ ] 数据库使用强密码；`application-dev.yml`、`database_config.json`、keystore、`local.properties` 均不入库
- [ ] 管理端口 9090（actuator）不对公网暴露
- [ ] 正式发布 APK 时按需关闭明文流量：`-PhypermuxCleartext=false`（默认允许 http 便于自托管）
